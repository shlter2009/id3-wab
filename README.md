# ID3 Sit Web

브라우저에서 음악을 가져오고 MP3로 변환한 뒤 곡 정보와 앨범 커버를 확인하여 저장하는 음악 작업실입니다. 데스크톱 프로젝트 `shlter2009/id3-sit`의 변환 엔진을 공유하는 별도 웹 프로젝트입니다. GUI나 Tk 설치 없이 실행합니다.

## 기능

- 여러 오디오 파일 업로드, 드래그 앤 드롭, 허용된 직접 오디오 URL 가져오기
- 아티스트 이름·별칭 목록 추가·수정·삭제, 내보내기·가져오기
- 백그라운드 FFmpeg MP3 변환, MusicBrainz 검색, 후보 선택·직접 편집과 재검색
- ID3v2.3 태그와 Cover Art Archive 커버 내장, 커버 미리 보기·재시도·직접 이미지 업로드
- 같은 앨범의 다른 발매판 커버 검색과 원본 커버 보존, MP3 재인코딩 방지
- `아티스트 - 곡 제목.mp3` 다운로드 및 브라우저 미리 듣기
- 진행 상태, 실패 원인, 재시도, 같은 오디오의 중복 저장 방지
- 모바일 대응, 브라우저 세션별 파일 격리, 선택적 사이트 비밀번호
- 화면 상단·정보 확인 창의 실행 버전, 수정 내역, 새 배포 알림

검색 점수는 정답 확률이 아닙니다. 모든 곡은 변환 전에 제목·아티스트·앨범·연도·길이를 직접 확인합니다. 제목·아티스트·앨범·연도를 바꾸면 기존 검색 후보의 커버 연결을 해제합니다. 자동 검색이 실패해도 직접 입력하여 변환할 수 있습니다.

## 아티스트 목록과 검색 개선

메인 화면의 **아티스트 관리**에서 정식 이름(예: `Drake`)과 별칭(예: `드레이크`, 한 줄에 하나)을 추가하세요. 목록은 이 브라우저에 저장되므로 Render 서버가 재시작되어도 유지됩니다. 다른 기기·브라우저와 자동 공유되지는 않으며 **목록 내보내기·가져오기**로 옮길 수 있습니다. 브라우저 데이터를 지우기 전에는 목록을 내보내세요.

등록한 이름은 파일명의 앞·뒤 구분 없이 전체 구간이 일치할 때 인식합니다. `Wu-Tang Forever - Drake (128k).mp3`는 가수 `Drake`, 제목 `Wu-Tang Forever`로 읽습니다. 등록하지 않은 가수도 첫 검색에서 일치하지 않으면 제목·가수 순서를 바꾸어 검색하고, 필요하면 제목으로만 한 번 더 검색합니다. 일치한 후보와 재생 길이를 비교하여 정렬하되 저장 전에는 사용자가 곡과 앨범을 선택합니다. 여러 등록 가수로 해석될 때는 한 명을 임의로 확정하지 않습니다.

`(128k)`, `[256kbps]`, 괄호 없는 `128k`·`256k`, 전각 `（２５６ｋ）` 같은 품질 표기는 파일명뿐 아니라 기존 ID3 제목·가수, 직접 입력, 재검색, 최종 태그와 다운로드 파일명에도 같은 규칙으로 제거합니다. `Live`, `Remix`, 피처링과 `Part 2`, `128` 같은 단위 없는 숫자, `24K Magic`·`100K` 같은 제목은 유지합니다. 괄호 없는 `k` 표기는 일반적인 오디오 비트레이트 값에만 적용합니다. 기존 ID3 태그를 우선 읽으며 등록된 별칭은 정식 이름으로 정리합니다. 업로드 원본은 수정하지 않고, 정리한 표시 이름과 원래 이름(`source_name`)을 구분합니다.

목록을 바꾼 뒤 **대기 중인 곡에 적용** 또는 곡 정보 창의 **목록으로 다시 인식**을 사용하세요. 제목·가수를 직접 고친 경우에는 **입력 정보로 다시 검색**을 눌러 앨범 후보를 새로 받습니다. 완료된 곡은 **정보 수정**을 눌러 재검색하고 다시 확인할 수 있습니다. 같은 오디오를 다시 가져와 확인한 경우에도 기존 출력의 이름·태그·커버를 갱신하고, 그 출력을 공유하는 작업들의 다운로드를 함께 갱신합니다.

긴 업로드 파일명은 저장용 이름과 분리하여 전체를 보존합니다. `JUSTHIS - Do Not Go Gentle Into That Good Night [Do Not Go Gentle Into That Good Night II]ㅣLyrics가사.mp3`에서는 `Lyrics가사`를 제거하고 대괄호의 앨범명을 힌트로 분리합니다. `Live`, `Remix`, `Part II` 같은 버전 표기는 유지합니다. 검색 결과의 개별 아티스트 크레딧을 비교하므로 피처링한 가수도 인식합니다. 가수 이름과 같은 제목의 엉뚱한 곡은 대체 결과로 채우지 않습니다.

검색 결과 없음과 네트워크 오류를 구분합니다. MusicBrainz HTTP 429·503은 서비스 혼잡으로 표시하며 재검색할 수 있습니다. 정보 확인 창에는 실제 검색한 제목·가수·앨범 힌트와 후보 수를 표시합니다.

## 버전과 수정 내역

현재 버전은 **v0.3.0**입니다. 로그인 전부터 화면 상단과 **현재 버전 / 수정 내역 보기**에서 확인할 수 있고, 모바일 화면과 곡 정보 확인 창에도 표시됩니다. 버전은 `music_manager/release.py` 한 곳에서 관리하며 패키지·HTML·정적 파일 주소·API에 함께 적용합니다. 이후 사용자에게 보이는 수정마다 버전을 올리고 `HISTORY`에 수정 내용을 추가합니다(`AGENTS.md` 참조).

`/version.json`은 로그인 없이 버전·수정 내역과 Render의 `RENDER_GIT_COMMIT` 앞 12자리 `revision`을 반환합니다. `/healthz`와 작업 목록 API도 버전을 반환합니다. HTML·정적 파일은 재검증하며, 열린 화면의 버전보다 서버가 새로 배포되면 새로고침 안내를 표시합니다. 화면 버전을 임의로 최신 번호로 바꾸지 않아 오래된 화면과 새 배포를 구분할 수 있습니다.

## 앨범 커버

앨범 후보를 선택하면 커버를 찾아 미리 보여줍니다. 선택한 발매판에 그림이 없으면 MusicBrainz에서 같은 release group으로 확인된 다른 발매판을 최대 3개까지 확인하고, 같은 release group의 대표 커버도 확인합니다. 관계가 확인되지 않은 동명 앨범의 이미지는 자동 사용하지 않습니다. 찾지 못하거나 네트워크 오류가 발생하면 원인과 **커버 찾기 / 재시도**, **이미지 올리기**를 제공합니다.

직접 올리는 이미지는 JPEG·PNG·WebP, 최대 10 MiB·1,600만 화소입니다. 방향을 보정하고 최대 1024×1024 JPEG로 저장합니다. **커버 없이 저장**을 선택하면 온라인 커버를 자동으로 다시 붙이지 않습니다. 제목·가수·앨범·연도를 바꾸면 이전 검색 커버는 연결을 해제합니다. 별칭을 정식 아티스트 이름으로 바꾸는 경우에는 같은 가수임을 확인해 커버 연결을 유지합니다.

이미 MP3인 입력은 오디오 패킷을 복사하고 ID3 태그·커버만 새로 기록합니다. 다른 오디오 형식만 MP3로 인코딩하며, 원본 파일은 수정하지 않습니다.

## 로컬 실행

Python 3.11 이상, FFmpeg가 필요합니다. macOS에서는 `brew install ffmpeg`, Windows에서는 FFmpeg를 설치하여 PATH에 추가하세요.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m music_manager.web
```

Windows PowerShell에서는 `.venv\Scripts\python`을 사용합니다. 기본 포트는 8000, 기본 바인딩은 로컬 머신입니다. 터미널에서 실행 후 브라우저 주소창에 `127.0.0.1:8000`을 입력하세요.

## Docker

```sh
docker build -t id3-sit-web .
python scripts/container_smoke.py
docker run --rm -p 8000:8000 --name id3-sit-web id3-sit-web
```

FFmpeg가 이미지에 포함되며 비루트 사용자로 실행합니다. 상태 확인 경로는 `/healthz`입니다. 빌드 환경이 기업 TLS 프록시를 사용하는 경우 선택적 BuildKit secret `build_ca`로 기존 신뢰 CA 번들을 전달할 수 있습니다. TLS 및 패키지 서명 검증을 비활성화하지 않습니다.

## Render 배포

이 저장소의 `render.yaml`은 무료 Docker 웹 서비스와 상태 확인, HTTPS 쿠키, 무작위 사이트 비밀번호·세션 서명 키를 설정합니다.

1. Render에서 GitHub 계정을 연결하고 이 저장소에 접근을 허용합니다.
2. **New → Blueprint**에서 `shlter2009/id3-wab` 저장소를 선택합니다.
3. `render.yaml`을 적용하고 배포 완료를 기다립니다.
4. 서비스 대시보드의 실제 `https://…onrender.com` 주소로 접속합니다. 주소는 서비스 생성 후 Render가 발급합니다.
5. Environment에서 생성된 `ID3_WEB_PASSWORD`를 확인하고 사이트 접속 비밀번호로 사용합니다. 비밀번호를 저장소나 채팅에 올리지 마세요.

[Render 배포 시작](https://render.com/deploy?repo=https://github.com/shlter2009/id3-wab)

이미 운영 중인 [id3-sit-web](https://id3-sit-web.onrender.com)은 새 서비스를 만들지 않고 기존 서비스를 갱신합니다. Settings에서 Repository가 `shlter2009/id3-wab`, Branch가 `main`인지 확인하세요. **Manual Deploy → Deploy latest commit**으로 최신 커밋을 배포하고 **Live** 상태를 확인한 뒤 사이트를 새로고침하세요. 이후 자동 배포를 사용하려면 해당 서비스의 Auto-Deploy를 커밋 배포로 설정합니다. 화면 상단 `v0.3.0` 또는 `/version.json`의 `version`으로 반영 여부를 확인할 수 있습니다. 재검색·커버 편집 영역이 없는 화면은 이번 변경 이전의 화면입니다.

이 링크는 배포 설정을 여는 링크이며, 배포가 완료된 웹사이트 주소는 아닙니다. 무료 인스턴스는 유휴 시 중지되거나 재시작될 수 있고 디스크가 영구적이지 않습니다. 완성된 파일은 즉시 다운로드하세요. 유료 플랜이나 영구 디스크는 이 구성에서 생성하지 않습니다.

## 환경 변수

| 이름 | 기본값 / 용도 |
| --- | --- |
| `HOST` | 로컬 `127.0.0.1`, 컨테이너 `0.0.0.0` |
| `PORT` | 기본 `8000`, Render Blueprint `10000` |
| `ID3_WEB_SECRET` | 쿠키 서명 키. Render가 생성. 로컬 미지정 시 재시작마다 무작위 생성 |
| `ID3_WEB_PASSWORD` | 사이트 접속 비밀번호. Render가 생성. 로컬 미지정 시 비밀번호 없이 사용 |
| `ID3_HTTPS` | HTTPS 배포 시 `true`, 로컬 HTTP에서는 미지정 |
| `ID3_WEB_DATA` | 업로드·출력 전용 폴더. 기본 `web-data` |
| `ID3_DOWNLOAD_HOSTS` | 쉼표로 구분한 직접 다운로드 허용 호스트. 기본 `archive.org,*.archive.org,upload.wikimedia.org` |

다운로드 URL에는 권한 확인이 필요합니다. YouTube 페이지·스트림 추출, DRM·접근 제한 우회는 지원하지 않습니다. URL 가져오기는 허용된 공개 호스트와 리디렉션만 처리하고 내부 네트워크 주소는 거부합니다. API 서버에는 음악 검색 제목·아티스트가 전송됩니다. MusicBrainz, Cover Art Archive 및 Archive.org에 대한 외부 HTTPS 연결이 필요합니다.

## 데이터와 운영 범위

파일당 최대 64 MiB, 세션당 최대 20개 작업, 프로세스당 최대 100개 작업을 허용합니다. 동시 작업 스레드는 2개입니다. 같은 세션의 라이브러리 쓰기는 직렬화합니다. ID3v2.3 UTF-16 태그와 UTF-8 중복 인덱스를 사용합니다.

브라우저 쿠키를 잃으면 기존 파일에 접근할 수 없습니다. 작업 목록은 메모리에 있으며 서버 재시작 시 초기화됩니다. 완료 파일의 다운로드를 우선하세요. 비활성 세션의 데이터는 24시간 경과 후 새 작업 생성 시 정리합니다. 작업 삭제 시 해당 입력 파일과 참조되지 않는 출력 파일을 지웁니다. 진행 중 작업은 완료 후 삭제할 수 있습니다. 처리 중 취소 기능은 없습니다.

중복은 정규화한 디코딩 PCM 해시로 판단합니다. 생성한 MP3를 다시 가져오는 경우도 판별합니다. 손실 압축 방식이 다른 같은 곡을 음향 지문으로 인식하는 기능은 없습니다. 웹에서 중복 곡의 정보를 다시 확인하면 기존 MP3의 오디오를 복사해 확인한 태그·커버와 새 이름으로 갱신합니다. 중복 MP3를 추가로 남기지 않으며 원본 파일은 보존합니다. 서버의 출력 파일과 인덱스를 외부에서 직접 수정하지 마세요.

현재는 단일 서버 프로세스·단일 인스턴스를 위한 개인용/소규모 웹앱입니다. 대규모 공개 서비스에 필요한 사용자 계정, 요금제, 분산 작업 큐, 객체 저장소는 포함하지 않습니다. 브라우저별 파일은 분리되지만 비밀번호 하나를 공유하는 개인 작업실로 운영하는 것을 권장합니다.

## 테스트

```sh
python -m pytest -q
python scripts/web_smoke.py
```

핵심 및 API 테스트는 짧은 합성 오디오와 모의 메타데이터를 사용합니다. 실제 FFmpeg, Mutagen, HTTP 쿠키·세션, 다운로드 응답을 검증합니다. 브라우저 테스트에는 Chromium이 필요합니다. 시스템 Chromium이 없으면 `python -m playwright install chromium`을 실행하거나 `CHROMIUM_PATH`에 설치된 브라우저 경로를 설정하세요. 브라우저 테스트는 아티스트 추가·수정·삭제·저장 유지·목록 가져오기, 긴 파일명 보존과 앨범 힌트 분리, 재검색, 커버 미리 보기와 직접 추가, 변환·다운로드·중복·모바일 화면, 버전·수정 내역·새 배포 안내를 실제로 실행합니다.

실제 MusicBrainz 및 Cover Art Archive 연결은 배포 환경의 외부 네트워크 정책에 따라 별도로 확인해야 합니다. 개발 환경에서 실제 업로드 사례의 MusicBrainz 검색과 Cover Art Archive 커버 수신 및 ID3 내장을 검증했습니다. 웹 URL 가져오기는 별도로 호스트 허용 목록·공개 IP 검증을 수행하므로 개발 환경의 DNS 제약으로 실패할 수 있습니다. 배포 사이트 접근은 개발 환경의 프록시 정책으로 차단될 수 있으며, 로컬 검증과 실제 배포 확인은 구분합니다.
